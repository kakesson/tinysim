A when-clause fires at the instant its condition becomes true. The condition becomes a zero-crossing function handed to the integrator, which stops exactly there; the body then runs, reinit jumps the velocity, and integration restarts from the new state.

The model - BouncingBall -- bouncing_ball.tiny

// State events and state jumps: a ball bouncing on the floor.
model BouncingBall
  parameter Real g = 9.81 "gravity [m/s2]";
  parameter Real e = 0.8  "coefficient of restitution [-]";
  Real h(start = 1.0) "height [m]";
  Real v(start = 0.0) "velocity [m/s]";
equation
  der(h) = v;
  der(v) = -g;
  when h < 0 then
    reinit(v, -e * v);
  end;
end BouncingBall;


// A warning worth reading: this model shows ZENO BEHAVIOUR.  The bounces come
// infinitely often in finite time, which no simulator can follow.  Once they
// are smaller than the event tolerance the contact is no longer detected, the
// condition h < 0 stays true, it never re-arms, and the ball falls through the
// floor.  Simulate to 3 s and it looks right; simulate to 20 s and it does
// not.  The honest fix is to model the resting contact, not to tune the
// tolerance -- see docs/pipeline.md.

contract NeverSinksThroughTheFloor for BouncingBall
  "the ball stays on top of the floor and never gains energy"
assume
  at start h > 0;
  0 < e and e < 1;
guarantee
  always h >= -0.001;
  always g * h + v ^ 2 / 2 <= g * 1.0 + 1e-9;
end NeverSinksThroughTheFloor;

How this system is actually solved

The blocks above are the plan. This is the procedure that follows from it: what happens to each block, what happens before the first step, and what happens when an event interrupts.

1. Once, before the first step: initialization

Every state simply takes its start value; no equations have to be solved yet:

h = 1, v = 0

2. At every evaluation: the continuous system

The integrator supplies the states h, v, the parameters, time, and asks what the derivatives are. Everything else is unknown and has to be computed, in the order the sorting found:

  1. der(h) := vrearranged directly from der(h) = v
  2. der(v) := -grearranged directly from der(v) = -g

The derivatives der(h), der(v) go back to the integrator. Every other value computed on the way is kept as a result, and the variables that alias elimination removed are recovered from the ones that survived.

3. Whenever a condition changes: the hybrid part

A when is not tested at the output points. Each condition was compiled into a crossing function that is positive exactly while the condition holds, and it is computed alongside the derivatives at every evaluation above:

conditionwatched as
when h < 0-h

The instant a crossing function passes zero upwards, the continuous system stops -- it is only valid until then -- and the body of that when runs:

  1. when h < 0 becomes true: the state v jumps to -(e * v)

Integration then restarts from the updated state: a hybrid simulation is a sequence of continuous segments, one per event, not one long solve. A condition that is already true cannot fire again until it has gone false, which is what makes when a rising edge rather than a test.

How hard the simulator works to find that instant is chosen when you simulate, not here: events="locate" finds the crossing itself, "step" notices it only at the end of the step it happened in, and "off" never looks.

4. In between: the integrator

Between evaluations the integrator advances the states -- either choosing its own step size to meet a tolerance, or taking the fixed step you gave it. That is the only part of this whole pipeline that TinySim does not do itself.

# ==========================================================================
# Simulation code generated by TinySim for model 'BouncingBall'.
#
# 2 equations, 2 unknowns, sorted into 2 blocks (no algebraic loops)
# States: h, v
#
# Dots in model names become double underscores here: c.v -> c__v.
# ==========================================================================

from math import (sin, cos, tan, asin, acos, atan, atan2, exp, log,
                  log10, sqrt, tanh, fabs as abs)
import numpy as np
from scipy.optimize import fsolve


def _solve_block(residual, guess, block, unknowns, t):
    """
    Solve one algebraic block numerically.

    An iterative solver needs a starting point, and a bad one can
    make it fail on a system that has a perfectly good solution --
    which is exactly why `start` values matter for the variables of
    an algebraic loop.  This tries the remembered guess first, then
    a fresh start from zero, and refuses to continue quietly if
    neither works.
    """
    for attempt in (guess, [0.0] * len(guess)):
        values, _, flag, message = fsolve(residual, attempt,
                                          full_output=True)
        if flag == 1:
            return values
    raise RuntimeError(
        'block %d (%s) did not converge at t = %g: %s'
        % (block, unknowns, t, message.strip()))


def evaluate(t, x, p, d, guess=None):
    """
    Solve the simulation equations of model 'BouncingBall'.

    t     : time
    x     : state vector, in the order listed below
    p     : dict of parameter values, keyed by model name
    d     : dict of discrete-variable values
    guess : dict used to remember iteration start values
    """
    guess = {} if guess is None else guess

    # ---- states: supplied by the integrator ----
    h = x[0]    # h -- height [m]
    v = x[1]    # v -- velocity [m/s]

    # ---- parameters: constant during simulation ----
    e = p['e']    # e -- coefficient of restitution [-]
    g = p['g']    # g -- gravity [m/s2]

    # ---- block 1: solve for der(h)  [explicit]
    #        der(h) = v
    der_h = v

    # ---- block 2: solve for der(v)  [explicit]
    #        der(v) = -g
    der_v = -g

    # ---- results ----
    der = np.array([der_h, der_v])
    variables = {
        'h': h,
        'v': v,
        'der(h)': der_h,
        'der(v)': der_v,
    }
    # ---- event margins: positive while the condition holds ----
    #        when h < 0
    events = [-h]
    return {'der': der, 'variables': variables, 'events': events}

The thermostat has no state jump at all. What its events change is a discrete variable, which is held constant between events and simply enters the differential equation as a number.

The model - Thermostat -- thermostat.tiny

// A discrete variable switched by two when-clauses: hysteresis control.
model Thermostat
  parameter Real Tset = 20  "setpoint [degC]";
  parameter Real band = 1   "hysteresis half-width [degC]";
  parameter Real k = 0.1    "heat loss coefficient [1/s]";
  parameter Real P = 5      "heater power [degC/s]";
  parameter Real Tamb = 5   "ambient temperature [degC]";
  Real T(start = 15)        "room temperature [degC]";
  discrete Real on(start = 1) "heater state, 0 or 1";
equation
  der(T) = -k * (T - Tamb) + P * on;
  when T > Tset + band then
    on = 0;
  end;
  when T < Tset - band then
    on = 1;
  end;
end Thermostat;


contract KeepsTheRoomComfortable for Thermostat
  "the room reaches the band quickly, and the heater switches when it should"
assume
  always Tamb < Tset - band;              // the room can actually get cold
  P > 0;                                  // and there is a heater
guarantee
  eventually within [0, 60] T >= Tset - band;
  after 60 T stays within [Tset - band - 0.5, Tset + band + 0.5];
  whenever T > Tset + band then on == 0 within [0, 0.1];
  whenever T < Tset - band then on == 1 within [0, 0.1];
end KeepsTheRoomComfortable;

                  log10, sqrt, tanh, fabs as abs)

    Solve one algebraic block numerically.

    An iterative solver needs a starting point, and a bad one can
    make it fail on a system that has a perfectly good solution --
    which is exactly why `start` values matter for the variables of
    an algebraic loop.  This tries the remembered guess first, then
    a fresh start from zero, and refuses to continue quietly if

def evaluate(t, x, p, d, guess=None):
    """
    Solve the simulation equations of model 'Thermostat'.

    t     : time
    x     : state vector, in the order listed below
    p     : dict of parameter values, keyed by model name
    d     : dict of discrete-variable values
    guess : dict used to remember iteration start values
    """
    guess = {} if guess is None else guess

    # ---- states: supplied by the integrator ----
    T = x[0]    # T -- room temperature [degC]

    # ---- parameters: constant during simulation ----
    P = p['P']    # P -- heater power [degC/s]
    Tamb = p['Tamb']    # Tamb -- ambient temperature [degC]
    Tset = p['Tset']    # Tset -- setpoint [degC]
    band = p['band']    # band -- hysteresis half-width [degC]
    k = p['k']    # k -- heat loss coefficient [1/s]

    # ---- discrete variables: constant between events ----
    on = d['on']    # on -- heater state, 0 or 1

    # ---- block 1: solve for der(T)  [explicit]
    #        der(T) = -(k * (T - Tamb)) + P * on

        'T': T,
        'on': on,
        'der(T)': der_T,
    }

    #        when T > Tset + band
    #        when T < Tset - band
    events = [T - Tset - band, -T + Tset - band]

The experiment script

The page above was produced by this script; it is included so the numbers can be traced back to the code that made them.

"""
Experiment 3 -- hybrid models: events, state jumps and discrete variables.

    python experiments/03_hybrid_events.py

The bouncing ball shows `reinit`, a jump in a continuous state.  The thermostat
shows a discrete variable switched by two `when` clauses.  Both are simulated
as a *sequence* of continuous segments, one per event.

    python experiments/03_hybrid_events.py --html
"""

import pathlib

import matplotlib.pyplot as plt

import setup_path  # noqa: F401  (lets this run without installing TinySim)
import tinysim
from tinysim import htmlreport

EXAMPLES = pathlib.Path(__file__).resolve().parent.parent / "examples"
FIGURES = pathlib.Path(__file__).resolve().parent.parent / "figures"
FIGURES.mkdir(exist_ok=True)

page = htmlreport.start(
    __file__,
    title="Experiment 3 - hybrid models",
    subtitle="Events, state jumps and discrete variables, in two small models")

# ---------------------------------------------------------------------------
# A bouncing ball: one state event, applied over and over.
# ---------------------------------------------------------------------------
ball = tinysim.load(EXAMPLES / "bouncing_ball.tiny", "BouncingBall")
tinysim.explain(ball, "events,code")

page.add_text("""
    A when-clause fires at the instant its condition becomes true. The
    condition becomes a zero-crossing function handed to the integrator, which
    stops exactly there; the body then runs, reinit jumps the velocity, and
    integration restarts from the new state.
    """)
page.add_source(EXAMPLES / "bouncing_ball.tiny", title="The model - BouncingBall")
page.add_model(ball, title="How BouncingBall was compiled")

# Stop at 3 s.  Past that the bounces become smaller than the event tolerance,
# they stop being detected, and the ball sinks through the floor -- the classic
# Zeno artefact, which the model itself cannot avoid.
bounces = tinysim.simulate(ball, stop=3.0, points=3001)
print(f"\n{len(bounces.events)} bounces:")
for event in bounces.events:
    print("   ", event)

figure = tinysim.plot(bounces, ["h", "v"], separate=True,
                      title="Bouncing ball: dotted lines mark the events")
figure.savefig(FIGURES / "bouncing_ball.png", dpi=150)
page.add_result(bounces, ["h", "v"], title="The simulation - bouncing ball")
page.add_figure(figure, "Height and velocity. Each dotted line is an event: "
                        "the integration stopped there, the velocity was "
                        "reversed, and a new segment began.")

# ---------------------------------------------------------------------------
# A thermostat: a discrete variable, switched by two conditions.
# ---------------------------------------------------------------------------
thermostat = tinysim.load(EXAMPLES / "thermostat.tiny", "Thermostat")
page.add_text("""
    The thermostat has no state jump at all. What its events change is a
    discrete variable, which is held constant between events and simply enters
    the differential equation as a number.
    """)
page.add_source(EXAMPLES / "thermostat.tiny", title="The model - Thermostat")
page.add_model(thermostat, title="How Thermostat was compiled")

control = tinysim.simulate(thermostat, stop=200.0, points=4001)
print(f"\nthermostat switched {len(control.events)} times")

figure, (temperature, heater) = plt.subplots(2, 1, sharex=True, figsize=(8, 5))
temperature.plot(control.time, control["T"])
temperature.axhline(21, color="grey", linestyle=":")
temperature.axhline(19, color="grey", linestyle=":")
temperature.set_ylabel("T [degC]")
temperature.set_title("Thermostat: the temperature stays inside the band")
temperature.grid(alpha=0.3)

heater.step(control.time, control["on"], where="post", color="tab:red")
heater.set_ylabel("heater on")
heater.set_xlabel("time [s]")
heater.set_ylim(-0.1, 1.1)
heater.grid(alpha=0.3)
figure.tight_layout()
figure.savefig(FIGURES / "thermostat.png", dpi=150)
print(f"wrote figures to {FIGURES}")
page.add_result(control, ["T", "on"], title="The simulation - thermostat")
page.add_figure(figure, "The temperature stays inside the hysteresis band "
                        "because the heater switches at its edges.")
page.finish()
